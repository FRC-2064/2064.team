## The loop

A good mechanism is not the first idea on the whiteboard. It is the idea that still works after a requirement, a second concept, a prototype, and a drive-team test. The same loop covers an XRP launcher and a competition subsystem.

| Step | You are doing | You are done when |
| --- | --- | --- |
| 1. Problem | Name the job and the limits | One sentence a new member can repeat, plus one constraint |
| 2. Options | More than one way to do it | Two concepts, scored against the requirement |
| 3. Prototype | Prove the motion cheaply | Wood, cardboard, or PLA has shown the geometry |
| 4. Test | Let the driver run it | A failure is written down, and the CAD changes from that |
| 5. Build | Cut the thing you tested | Not a new idea that skipped the prototype |

## Problem, then options

"Score fuel into the active hub" is a problem. "Build a cool robot" is not. Constraints are the limits: weight, frame perimeter, budget, what this shop can cut. Criteria are how you will know it worked.

More than one idea. Mechanical, electrical, programming, and drive each get a say before a concept is locked. A wild idea is allowed. Yes Griffin, even a trebuchet. Pick against the requirement, not against how exciting it looks.

Draw the winner in Onshape. Prove the motion in wood, cardboard, or PLA before competition plate. Put the drive team on it. A mechanism a mentor can run slowly is not the same as one a student can run in a match. Change the model from what the test showed.

## Mechanical foundation

These are the ideas behind a legal, buildable part. Module 8 goes further. This is the floor.

* **Structure.** The frame holds everything else and has to survive a hit. Kit extrusion or plate, bolted or riveted so a bent corner can be swapped. A pretty sketch that cannot be held in the shop is not a design.
* **Materials.** Aluminum is the usual structure. Steel is for small, high-load parts. Plastic and plywood are for prototypes and some bumpers. Heavier is not stronger if it blows the weight limit.
* **Actuators.** A motor makes rotation. A gearbox trades speed for torque. A motor controller sits between the PDH and the motor. Pick the motor for the job, not for the brand you recognize.
* **Drivetrain.** Tank runs each side together. Swerve steers each corner. If the drivetrain fails, the mechanism on top does not matter.
* **Subsystem.** An intake, a shooter, or a climber is its own loop: requirement, prototype, test, then it joins the robot. It uses the same power and control rules as the drivetrain.
