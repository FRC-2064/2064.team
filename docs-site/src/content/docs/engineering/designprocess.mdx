## The loop

A good mechanism is not the first idea on the whiteboard. It is the idea that still works after a requirement, a second concept, a prototype, and a drive-team test. The same loop covers an XRP launcher and a competition subsystem.

| Step | You are doing | You are done when |
| --- | --- | --- |
| 1. Problem | Name the job and the limits | One sentence a new member can repeat, plus one constraint |
| 2. Options | More than one way to do it | Two concepts, scored against the requirement |
| 3. Prototype | Prove the motion cheaply | Wood, cardboard, or PLA has shown the geometry |
| 4. Test | Let the driver run it | A failure is written down, and the CAD changes from that |
| 5. Build | Cut the thing you tested | Not a new idea that skipped the prototype |

"Score fuel into the active hub" is a problem. "Build a cool robot" is not. More than one idea. A wild idea is allowed. Yes Griffin, even a trebuchet. Pick against the requirement, not against how it looks. Draw the winner in Onshape, then prove it before competition plate.

## Mechanical foundation

The floor under that loop. Module 8 goes further.

<CardGrid>
  <Card title="Structure" icon="puzzle">
    The frame holds everything else and has to survive a hit. Bolted or riveted so a bent corner can be swapped.
  </Card>
  <Card title="Materials" icon="document">
    Aluminum for structure. Steel for small high-load parts. Plastic and plywood for prototypes. Heavier is not stronger if it blows the weight limit.
  </Card>
  <Card title="Actuators" icon="setting">
    A motor makes rotation. A gearbox trades speed for torque. Pick the motor for the job, not the brand.
  </Card>
  <Card title="Drivetrain" icon="rocket">
    Tank runs each side together. Swerve steers each corner. If this fails, the mechanism on top does not matter.
  </Card>
  <Card title="Subsystem" icon="approve-check">
    An intake, shooter, or climber is its own loop, then it joins the robot.
  </Card>
</CardGrid>
