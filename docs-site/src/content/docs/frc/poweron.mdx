**Objective:** Power on last season's robot, connect the driver station, and explain what Enable actually does. The robot changes every year. This sequence mostly does not.

:::note[📋 Prerequisites: Before You Start]
Ensure you have successfully completed and received mentor sign-off for the following modules:

- [x] **1.1.2 - Bot Basics** is required. You need to already know the battery, main breaker, radio, roboRIO, and driver station.
- [x] Current safety clearance is required before the robot is powered.
:::

:::danger[STOP]
Do not enable the robot until a mentor is present, the robot is on the cart or blocked up, and every person is clear of wheels and mechanisms. Disabled is the safe state. Enable means the code can command motors.
:::

## What you are turning on

Three separate things have to be alive before a stick does anything:

1. **Robot power.** Battery, main breaker, PDH. This feeds motors, the roboRIO, and the radio.
2. **A link.** Ethernet, USB, or the robot radio. This is how the laptop talks to the roboRIO.
3. **Driver Station software.** The FRC Driver Station on the drive laptop. It reads the controllers, sends Enable, and shows faults.

A charged battery with no link still cannot be driven. A perfect link with the main breaker off still cannot be driven.

---

## Step 1: Make the robot safe to power

Do this before the battery is plugged in.

* Robot on the cart, or drive wheels off the floor. A robot that can reach the ground can drive off the cart.
* Mechanisms that swing, shoot, or climb are clear of people and of the ceiling.
* Battery is the team competition pack, not a random 12-volt battery. Case is not swollen. Terminals are tight.
* Anderson SB50 is the only legal battery connector. Do not jam a loose connector. If it does not seat, stop and get a mentor.
* Area around the robot is clear. Say "powering on" so the people next to it look up.

Voltage worth knowing: a rested competition battery should read about 12.5–13.0 V on the Driver Station. Under about 12.0 V at rest, do not practice. Swap the pack. A sagging battery causes brownouts, and brownouts look like a code bug.

---

## Step 2: Power the robot

1. Plug the battery into the robot's SB50. Red to red, black to black. The connector is polarized; force means it is wrong.
2. Wait until the roboRIO and radio have booted. Lights settle after several seconds. Enabling in that window fails for no useful reason.
3. Turn the main breaker **on**. It is the large red 120 A breaker. This is the robot's power switch.
4. Confirm the radio has power. On a VH-109, the status light comes up after boot. No radio light usually means the radio breaker on the PDH is open, or the battery is not actually connected.

To shut down: Driver Station **Disabled**, main breaker **off**, then unplug the battery if the robot is being stored or worked on. Unplugging under load pits the connector.

---

## Step 3: Connect the driver station

The drive laptop runs the FRC Driver Station. Team number must match the robot. Controllers plug into that laptop, not into the robot.

Use the first method that fits the shop that day.

| Method | When to use it | What "good" looks like |
| --- | --- | --- |
| Ethernet to the radio | Most reliable shop connection | DS shows Communications and Robot Code |
| Robot Wi-Fi | No cable, pit or practice field | Laptop joined to the team network, then the same two lights |
| USB tether to the roboRIO | Radio or network is the thing you are debugging | Communications up without the radio in the path |

Wi-Fi notes:

* Connect to the robot radio's network, not school Wi-Fi. School Wi-Fi will never see the roboRIO.
* Forget other saved robot networks if the laptop keeps joining last year's radio.
* If Ethernet is plugged in, use Ethernet. A laptop on both Wi-Fi and a cable often picks the wrong path.

In the Driver Station, select **Teleoperated** for stick practice. Leave the robot **Disabled** until Step 5. The mode dropdown does not move motors. Only Enable does.

---

## Step 4: Read the three status lights

The Driver Station has three indicators that matter more than the voltage graph.

* **Communications.** Laptop is talking to the roboRIO. Red means no link. Check cable, Wi-Fi network, team number, and that the radio finished booting.
* **Robot Code.** A program is running on the roboRIO. Red means code crashed or never deployed. Cycling power does not fix a missing deploy.
* **Joysticks.** The laptop sees the controller. Unplug and replug USB. Check the USB device list in the DS. Axes should move before you enable.

**Brownout** means battery voltage collapsed under load. The roboRIO sheds outputs to stay alive. Stop, Disabled, swap or charge the battery. Do not keep enabling.

---

## Troubleshooting, in order

Change one thing, then look at the lights again.

1. Main breaker on, battery plugged in, radio light on.
2. Laptop on the robot network or on the Ethernet tether, not on school Wi-Fi.
3. Team number in the Driver Station matches this robot.
4. Communications green. If not, reseat the Ethernet at the laptop and at the radio.
5. Robot Code green. If not, a programmer has to deploy. That is not a battery problem.
6. Joysticks green, and the stick you are holding is the one in the USB order the code expects.
7. Still dead: Disabled, breaker off, mentor. Do not start swapping CAN wires.

---

## Step 5: Enable

* Mode is Teleoperated.
* Communications, Robot Code, and Joysticks are green.
* Mentor is watching. Wheels are up, or the path is clear.
* Press **Enable**.

The robot can now follow the code. Press **Disable**, or the space bar, the moment anything unexpected moves. Disable is the emergency stop for shop practice. Use it early.

Enable does not map buttons. It only allows the already-running code to act on the controllers.

---

## How buttons get their jobs

The controller is just axes and button numbers. The laptop reads them. The Driver Station forwards them. The robot code decides what each number means.

A typical Xbox-style pad:

| Input | Usual job on 2064 | Where it is set |
| --- | --- | --- |
| Left stick | Drive translation | Code, drivetrain command |
| Right stick | Rotation, or swerve rotation | Code |
| Bumpers / triggers | Intake, score, climb | Code, bound to a command |
| Face buttons | Shift a mode, cancel, stow | Code |
| Start / Back | Leave unbound, or use as a safe action | Code |

The Driver Station **USB** tab shows the order. If two controllers are plugged in, USB order is the mapping. Swapping the ports swaps the driver and the operator. Plug them in the same ports every time, or the code will aim the operator stick at the drivetrain.

To see a mapping without enabling:

1. Disabled, Joysticks green.
2. Open the USB / joystick view in the Driver Station.
3. Press one button. Note the number that lights.
4. Ask the programmer which command that number calls.

Changing a button's job is a code change and a deploy, not a setting in the Driver Station. Write the agreed map on the drive-team sheet so practice and the pit use the same one.

---

## Shop rules for this robot

* Disabled before hands go inside the frame.
* Breaker off before connector work.
* No enabling from across the room.
* Call out "enabling" and "disabling."
* Last person to practice unplugs the battery or leaves the robot in the state the mentor asked for.
