## 1. Wire the Robot to Match the Code

The code below hardcodes these ports. Wire to this table or the code will move the wrong thing.

<Aside type="danger" title="Labels start at 1. Code starts at 0.">
The silkscreen printed on the XRP board counts from **1**. The code counts from **0**. The first motor connector on the board is printed `M1` and is addressed as `0` in `Constants.java`. **Always subtract one from the printed label when you write code.** This table already did that subtraction for you — plug into the label, type the number.
</Aside>

| Device | Plug into this printed port | Address in `Constants.java` |
| --- | --- | --- |
| Left drive motor | `M1` | Motor `0` |
| Intake wheel motor | `M2` | Motor `1` |
| Flywheel motor (through MOSFET) | `M3` | Motor `2` |
| Right drive motor | `M4` | Motor `3` |
| Intake arm servo | `S1` | Servo `4` |
| Gate servo | `S2` | Servo `5` |
| Left drive encoder | `DIO 5` / `DIO 6` | DIO `4` / `5` |
| Right drive encoder | `DIO 11` / `DIO 12` | DIO `10` / `11` |

**Why this matters:** Two numbering systems are in play at once, and mixing them is the single most common way to fry a build. The printed labels are for your hands; the code numbers are for the compiler. A motor plugged into `M3` but addressed as `3` in code runs the wrong mechanism, and a servo plugged into `S1` but addressed as `1` sits dead because servo numbers begin at `4`.

The encoder channels are deliberately chosen far from the motor connectors so the signal cables do not run alongside the power cables. If you change a port on the robot, change the matching line in `Constants.java` in Step 3, and nothing else.

<Aside type="note" title="If your silkscreen looks different">
Some XRP revisions print the servo headers `SERVO 1` / `SERVO 2` and the DIO block without numbers. The **right-hand column is authoritative** — it is what the code reads. Match the right column, and use the printed label only to find the physical connector.
</Aside>
